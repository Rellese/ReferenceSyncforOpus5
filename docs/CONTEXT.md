# ReferenceSync — рабочий контекст

Файл для быстрого ввода в курс дела. Читать первым.

## Что это

Приставка к Eagle. Пользователь сохраняет референсы в соцсетях,
программа находит их, даёт настроить имена, описания и нумерацию,
и импортирует в Eagle в хронологическом порядке.

Площадки: Instagram (готов на 98%), Pinterest (частично),
дальше Behance, Vimeo, Dribbble, Threads, X, Layers.

Запуск: `python -m app.reference_sync_gui`
Личный конфиг: `config/local.json` — вне git, у каждого свой.

## Структура

- `app/` — ядро; `app/ui/widgets.py` — элементы таблицы, делегаты, диалоги
- `data/legacy_pinterest/` — старые скрипты, не используются
- `tools/patch_*.py` — одноразовые скрипты правок, история изменений
- `_extracts/` — временные куски кода для обсуждения, удалить после

Ключевые модули: `reference_sync_gui.py` (интерфейс),
`instagram_sync.py` (оркестратор), `instagram_discover.py` (поиск),
`source_container_preview.py` (дерево папок для GUI),
`source_container_normalize.py` (папки для базы),
`eagle_import_staging.py` (импорт в Eagle).

## Контракт папок

- Instagram: `collection_id` как есть, плюс особый
  `ALL_MEDIA_AUTO_COLLECTION` — это общая лента, а не папка
- Адрес коллекции: `instagram.com/{user}/saved/collection/{id}/`
- Адрес общей ленты: `instagram.com/{user}/saved/all-posts/`
- CLI: `--collection "ID:NAME"`, можно повторять.
  Путь: GUI → `instagram_sync` → `instagram_discover`
- Результат: у каждого поста `containers: [{platform, kind, id, name}]`

Известное противоречие, не исправлено: `source_container_preview`
отдаёт сырой `id`, а `source_container_normalize` строит
`account:<user>:collection:<id>`. Свести к одному формату.

## Принятые решения

1. Тумблер «искать в выбранных папках» выключен — один проход по
   общей ленте, принадлежность к папкам не определяется. Осознанно:
   4300 постов сканируются ~20 минут, второй проход недопустим.
2. Тумблер включён — проход только по выбранным коллекциям, папка
   известна из адреса. Лимит «последние N» применяется к каждой
   папке отдельно.
3. Двух проходов не делаем никогда.
4. Рефакторинг мелкими шагами: каждый шаг проверяется запуском
   программы и отдельным коммитом.

## Сделано

- Элементы таблицы и делегаты вынесены в `app/ui/widgets.py`
  (главный файл: 8148 → 6703 строк)
- `instagram_discover` умеет сканировать выбранные коллекции
- Проброс папок через `instagram_sync`, кнопка «Продолжить»
  запускает реальный поиск

## Как работаем

Один коммит на одну правку, сразу push. Правки оформляются
скриптами `tools/patch_*.py` по принципу «всё или ничего»:
скрипт проверяет якоря и при несовпадении не меняет ничего.
Куски кода для обсуждения кладутся в `_extracts/`, не длиннее
120 строк — иначе не читаются целиком.
